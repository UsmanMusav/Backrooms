# Нейро-Мимик, ники и чат — 1.3.0

## Что работает сразу

В игре действительно выполняется **нейросетевой inference**, а не только переименованный автомат состояний. Вместе с игрой поставляются две небольшие обученные MLP: выбор намерения движения и распознавание темы сообщения. Они работают на CPU в браузере/EXE/сервере, без интернета, GPU, ключей, Python и загрузки моделей. Обучение выполнено на наших синтетических примерах, **не на переписке игроков**.

Намерения: идти за участником, вести к текущей цели, подождать, проверить ответвление, заманивать в боковой проход. Нейросеть выбирает намерение; проверяемые коллизии, поиск пути, анимация, задержки, раскрытие, урон и цели остаются игровой логикой. Скорость подстраивается под движение игрока, повороты сглажены, есть остановки и имитация использования фонаря. Это не гарантия неотличимости от человека и не чтение мыслей.

**Встроенная модель не является генеративной LLM.** Она распознаёт восемь тем коротких сообщений и выбирает авторские контекстные реплики. Свободный разговор на любые темы без отдельной LLM не поддерживается. Неизвестные формулировки могут распознаваться неверно. Архитектура, происхождение данных и ограниченные синтетические метрики: [`shared/ai/MODEL-CARD.md`](../shared/ai/MODEL-CARD.md).

## Ники и один общий чат

- Перед подключением задайте ник: до 18 символов, буквы/цифры/пробел/дефис/подчёркивание. Ники **людей в одной комнате** уникальны без учёта регистра после нормализации. Системные имена зарезервированы. Это не аккаунты и не глобальный реестр имён.
- В лобби есть поле **«Ваш ник» → «Сохранить»**. Смена ника гостя снимает готовность; в начавшемся раунде ник зафиксирован. Подтверждённый ник запоминается на этом устройстве.
- В игре **Enter или T** открывает чат, Enter отправляет, Esc закрывает. Кнопка **«ЧАТ»** работает и на сенсорном экране. Пока поле активно, WASD/F/E и мышь не управляют персонажем. Q — «Держимся вместе.».
- Это тот же канал, что в лобби, не второй чат. До 160 символов в сообщении; сервер ограничивает частоту. Сохраняются последние 40 строк в памяти комнаты, при входе в лобби они приходят новому участнику. Открытый чат показывает историю, время и ваш ник, закрытый — последние сообщения и индикатор нового. При выходе из комнаты клиентский буфер очищается.
- Мимик отправляет обычные строки под скопированным **ником и внешностью настоящего участника**, в том числе в комнате на одного человека. У него остаётся отдельный actor ID: он не получает управление чужим клиентом, роль ведущего или права игрока. Дополнительная смена маски возможна только вне близкой прямой видимости и не чаще раза в 12 секунд. Список в лобби содержит только людей. В офлайн-solo спутник по-прежнему представляется Сашей.
- Общий чат слышат все участники, включая погибших и Мимика. Приватных сообщений, микрофона, записи и клонирования голоса нет.

## Свободный диалог: необязательное серверное подключение к LLM

Для развёрнутой генерации реплик ведущий/оператор **общего игрового сервера** может подключить OpenAI-совместимый `POST /v1/chat/completions`. Та же модель выбирает высокоуровневое поведение и маску. Поддерживается ответ `choices[0].message.content` с JSON-объектом, не streaming и не отдельный Responses API.

**Сервис, ключ и большие языковые веса не предоставляются вместе с игрой.** Конкретная модель должна быть настроена оператором. Для локальной LLM отдельно установите совместимый сервер (например, Ollama) и языковую модель с поддержкой русского и JSON-ответов. Для удалённого сервиса могут взиматься платежи за токены; они не входят в игру. Не присылайте ключи в чат и не помещайте их в исходники или клиентские `VITE_*` переменные.

### Пример: локальная LLM и Windows EXE

Пример конфигурации, **не результат проверки конкретной языковой модели**:

1. В отдельно установленной Ollama загрузите модель, например `ollama pull qwen2.5:3b`. Запустите Ollama, если её служба ещё не работает. Выберите размер модели под память/производительность компьютера. Убедитесь, что её OpenAI-совместимый API слушает только loopback `127.0.0.1:11434`, не открывайте его в интернет.
2. В PowerShell, находясь рядом с EXE, задайте окружение **серверного приложения**:

```powershell
$env:MIMIC_LLM_URL = 'http://127.0.0.1:11434/v1/chat/completions'
$env:MIMIC_LLM_MODEL = 'qwen2.5:3b'
$env:MIMIC_LLM_TIMEOUT_MS = '5000'
& '.\Backrooms-Mimic-1.3.0-Windows-x64.exe'
```

3. Откройте **Кооператив → Создать комнату**, поле игрового сервера оставьте пустым. Можно начать одному; для друзей используйте обычный адрес сервера и код. Мимик появляется после начала раунда, не общается в лобби.
4. В лобби и раскрытом чате виден статус: «LLM настроена» **не означает**, что модель уже ответила. «LLM отвечает» появляется после принятого ответа; «LLM недоступна» означает переход на локальную нейросеть. Медленная модель, неверный JSON или исчерпанный лимит также включают fallback.

У сервера и всех участников должна быть версия 1.3.x, 1.4.x, 1.5.x или 1.6.x (протокол backrooms-v2); версии 1.1/1.2 не подключаются, поскольку в них не было предупреждения о внешней обработке чата. У гостей ничего для LLM настраивать не нужно. Их EXE может иметь свой встроенный сервер, но подключаться все должны к одному серверу ведущего. В режиме **«Начать игру» (офлайн solo)** используется встроенная MLP и короткие реплики; для чата с LLM создайте кооперативную комнату даже для одного игрока.

### Исходный production-сервер

После `npm ci && npm run build` можно скопировать `.env.example` в `.env`, отредактировать локально и запустить:

```sh
node --env-file=.env server/cli.mjs
```

`npm start` и EXE сами этот файл не читают; обычная клиентская загрузка `.env` в Vite не настраивает серверные `MIMIC_*` переменные. Альтернатива — переменные окружения процесса/менеджера секретов. EXE всегда читает только окружение процесса. В dev POSIX-оболочка, например:

```sh
MIMIC_LLM_URL=http://127.0.0.1:11434/v1/chat/completions MIMIC_LLM_MODEL=qwen2.5:3b npm run dev
```

### Настройки оператора

| Переменная | Значение / ограничение |
| --- | --- |
| `MIMIC_LLM_URL` | Полный URL chat/completions. Отсутствует — только локальные MLP, без внешних вызовов. URL с логином, паролем, query/hash или редиректами не поддерживается. |
| `MIMIC_LLM_MODEL` | Имя установленной/доступной модели, обязательно при URL. |
| `MIMIC_LLM_KEY` | Необязательный серверный Bearer-ключ из окружения/менеджера секретов. Для локальной Ollama обычно не нужен. |
| `MIMIC_ALLOW_REMOTE_AI` | Только `1` разрешает **удалённый HTTPS** endpoint и передачу игровых данных. По умолчанию запрещено. HTTP разрешён лишь для localhost/loopback. |
| `MIMIC_LLM_TIMEOUT_MS` | По умолчанию 5000 мс, допустимо 100–15000. Слишком медленная модель включает fallback. |
| `MIMIC_LLM_RPM` | Общий token bucket для всего процесса, по умолчанию 12 запросов/мин в среднем с кратким burst до 2; допустимо 1–60. Не на каждую комнату. |

Принятие удалённой обработки должно быть осознанным: в лобби показано предупреждение. Передаются последние **до 10 публичных строк текущего раунда**, ники/псевдонимы участников, видимые Мимику признаки движения/фонаря/дистанции, его положение и прогресс общих целей. Не передаются ключ, IP игроков, их системные файлы, микрофон, закрытая переписка или скрытые координаты людей. Провайдер при этом видит IP **игрового сервера** как отправителя HTTP-запроса и может хранить входные данные согласно собственным условиям. Локальная LLM тоже может вести собственные логи. Не отправляйте личную информацию или секреты в игровой чат.

Обычный сервер игры не пишет переписку на диск; история живёт в памяти комнаты до её удаления/перезапуска сервера. Изменения URL, ключа или модели требуют перезапуска серверного процесса. Неверная или небезопасная конфигурация останавливает запуск с ошибкой конфигурации, без вывода значений ключей. Сетевой сбой уже настроенного провайдера не останавливает игру.

## Ограничения и защита симуляции

- Примерно один план в 7,5 с на комнату; сообщение человека может ускорить следующий, но не чаще раза в 6 с. Не более одного незавершённого плана на комнату и двух запросов ко всему провайдеру одновременно. Общий лимит, сеть и задержка влияют на частоту ответов. Это **не мгновенный чат-бот**.
- Модель получает ограниченный JSON-контекст. Её ответ — лишь `follow/lead/wait/explore/lure`, существующие псевдонимы целей/масок, настройка фонаря, длительность 3–10 с и короткая фраза. Неизвестные поля/действия/маски отклоняются. Данные от игроков в промпте помечены как недоверенные, но поведение сторонней LLM не гарантируется.
- Реплики — только текст, HTML экранируется. Нет shell, tool calls, файлового доступа, выполнения сгенерированного кода, изменения URL или команд из чата. Ключ не включается в контекст модели, состояние комнаты или browser bundle. Сам провайдер, естественно, получает Bearer-ключ для авторизации своего API.
- При неверном JSON, HTTP-ошибке, превышении лимита, слишком большом ответе или таймауте игра продолжает работать с локальной MLP и ограниченными фразами; повторная попытка делается позже. Ответы не чаще раза в 5,5 с, есть задержка перед «набором» реплики.
- Завершение раунда, раскрытие Мимика, изменение состава и закрытие комнаты/сервера отменяют запрос. Старый ответ не попадает в следующий раунд, даже если провайдер проигнорировал отмену. Тики симуляции не ждут модель.
- Ники/чат не являются надёжной проверкой личности — подмена здесь намеренная игровая механика, о которой предупреждено до старта. Внешние аккаунты и личности реальных людей за пределами комнаты не используются.

## Что проверено для 1.3.0

Автоматические проверки: настоящая математика inference и веса, независимая синтетическая выборка policy, классификация коротких тем, имитация никнейма, коллизии/раунды, ограничение частоты, реальный HTTP **тестовый** endpoint формата chat/completions, таймауты, отмена и недоверенные ответы, реальные WebSocket-клиенты и браузерный интерфейс (включая мобильную ширину).

**Реальная внешняя LLM, конкретная Ollama-модель и её качество диалогов при подготовке выпуска не проверялись:** провайдер/оборудование/доступ не были предоставлены. Это не выдаётся за успешный live-тест нейросервиса. Windows GUI вручную в этой среде также не проверен; EXE остаётся неподписанной предварительной сборкой с требованиями WebView2 и Visual C++ x64.
